# Experimental Scoring

## Experiment

**AI Automation Test #1 — Brand Awareness & Market Entry**

## Purpose

The scoring framework was used to compare the three process configurations across multiple dimensions rather than evaluating them solely on process time.

The framework was designed to prevent efficiency from becoming the only measure of success.

---

## Scoring Framework

Each run was assessed against five dimensions:

| Dimension              | Maximum Score |
| ---------------------- | ------------: |
| Capacity / Efficiency  |             6 |
| Quality                |             6 |
| Human Control          |             6 |
| Risk / Safeguards      |             6 |
| Learning / Reusability |             6 |
| **Total**              |        **30** |

Each dimension was scored on a 0–6 scale.

The resulting total was used as a structured comparative assessment of the three configurations.

---

## Important Scoring Boundary

The scores are **experimental evaluation scores**, not externally validated scientific measurements.

They represent a structured judgement against the defined criteria and experimental conditions.

Their purpose is to make the comparison more explicit and reproducible than relying solely on narrative interpretation.

---

## Run A — Manual Control

### Score

> **28 / 30**

### Interpretation

Run A performed strongly in areas relating to human control and judgement.

Its principal weakness was capacity efficiency.

The manual process required approximately **464 minutes**, creating a substantial operational workload.

The configuration therefore scored well for:

* human authority;
* direct judgement;
* contextual interpretation;
* and conventional control.

It scored comparatively lower where the process depended heavily on human time and repetitive operational effort.

### Overall Assessment

Run A demonstrated that a human-led process could maintain strong control and quality, but at a significant capacity cost.

---

## Run B — AI-Engineered

### Score

> **28 / 30**

### Interpretation

Run B produced a substantial improvement in modelled process efficiency.

The process was reduced from approximately **464 minutes to 107 minutes**.

However, the introduction of AI created additional risks and highlighted the need for stronger governance and explicit responsibility boundaries.

The configuration therefore demonstrated strong potential for capacity recovery but required further optimisation before being treated as the preferred operating model.

### Overall Assessment

Run B demonstrated that AI could potentially transform the workload profile of the process, but efficiency alone was insufficient to establish the configuration as optimal.

---

## Run C — Optimised

### Score

> **30 / 30**

### Interpretation

Run C retained almost all of the modelled capacity benefit achieved by Run B while introducing additional controls and a formal learning mechanism.

The process was modelled at approximately **108 minutes**.

The slight increase in process time relative to Run B was accepted because the optimised configuration incorporated additional:

* safeguards;
* human approval;
* evidence controls;
* responsibility boundaries;
* and learning mechanisms.

### Overall Assessment

Run C represented the strongest configuration within the defined experimental framework because it achieved a more balanced combination of:

> **Capacity + Quality + Control + Risk Management + Learning**

## What the Scores Show

The scoring illustrates an important characteristic of the experiment.

### Run A

Strong control and quality, but significant operational workload.

### Run B

Significant capacity improvement, but additional governance requirements emerged.

### Run C

Retained the capacity improvement while strengthening control and safeguards.

The scores therefore support the conclusion that **optimisation should not be defined solely by reducing process time**.

---

## Why Run B Did Not Score Higher

Run B achieved the lowest modelled process time.

However, its score was constrained by the governance requirements exposed through AI integration.

This reflects the principle that:

> **A faster process is not automatically a better process.**

AI-enabled efficiency creates value only when the resulting process remains sufficiently controlled and reliable for its intended purpose.

---

## Why Run C Scored Highest

Run C was designed specifically to address the weaknesses identified in Run B.

It retained the modelled capacity benefit while introducing:

* clearer human-AI boundaries;
* stronger safeguards;
* explicit approval requirements;
* evidence and confidence considerations;
* and a structured learning stage.

The resulting score therefore reflects the **balance of the operating model**, not simply its process speed.

---

## Limitations of the Scoring

The scoring framework has several limitations.

The scores:

* were assigned within the experimental framework;
* depend on the defined evaluation criteria;
* are not statistically validated;
* are not independently assessed;
* and should not be generalised beyond the experiment.

Future tests should consider whether the scoring framework itself should be refined as more experimental evidence becomes available.

---

## Evidence Classification

The scoring represents a **structured experimental assessment** of the three process configurations.

It should be interpreted alongside:

* the experimental methodology;
* the reference dataset;
* the individual run documentation;
* the comparison results;
* and the stated evidence limitations.

The scoring is therefore one component of the evidence base rather than the sole basis for the experiment's conclusions.
